Drug Interaction and Dosage Matcher

Class project demo with made-up data. Not medical advice.

Check a patient's medications

Pick a sample patient or tap drugs to build a list. Every pair is looked up in the interaction hash table.

How it works

Input: Patient medication list of k drugs.

Output: Drug interactions among the meds, ordered by severity.

Algorithm: Generates all k(k-1)/2 medication pairs and queries canonical pair keys ("drugA|drugB") in an interaction hash table.

Time complexity: O(k2) expected time with O(1) hash lookups, vs O(k2 × m) scanning a list of m interactions.

Find two drugs that add up to a target

Uses hash-based 2-SUM. Leave the chips empty to search every drug, or pick a smaller set.

How it works

Input: Drug list, chosen field (cost/dose), target sum, and safety filter.

Output: Unique pairs of drugs whose values sum to the target.

Algorithm: 2-SUM with a hash table. Hashes each drug by its value, then for each drug checks if target - value exists in the table.

Time complexity: 2-SUM with a hash table: O(n) expected, vs O(n2) brute force.

Sorted drug list (binary search tree)

The list is an in-order traversal. Try select, rank and predecessor, or add and delete drugs to change the tree.

How it works

Input: Drugs sorted dynamically by name, monthly cost, or daily dose.

Output: In-order sorted list, tree height, k-th smallest element (select), rank, and predecessor.

Algorithm: Binary Search Tree (BST) augmented with subtree size counters at every node, plus left/right tree rotations.

Time complexity: Select, rank, search, and predecessor take O(h) time where h is tree height (O(log n) average, O(n) worst-case); in-order traversal is O(n).

Collision methods compared

Same 1009-slot table filled to different load factors. Avg probes is slots checked per successful lookup.

How it works

Input: Seeded random string keys inserted into a 1009-slot hash table at load factors 0.3, 0.5, 0.7, and 0.9.

Output: Collisions during insert and average probes per successful lookup.

Algorithm: Tests three collision methods: separate chaining, linear probing, and double hashing (with secondary hash step).

Time complexity: O(1) expected lookups; linear probing clusters as load factor α → 1 (~O(1/(1-α)2) probes), while double hashing avoids primary clustering (~O((1/α) ln(1/(1-α)))).
